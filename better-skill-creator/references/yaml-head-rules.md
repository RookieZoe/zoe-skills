# YAML 头部规则

`SKILL.md` 开头的 YAML 头部是通用 Skill 的声明面。先把它写对，再写正文。

## 必填字段

- `name`：必填。必须与 `SKILL.md` 所在目录名完全一致。
- `description`：必填。必须说明这个 skill 在什么条件下触发，不能只是功能简介。

## `name` 规则

- 只允许小写字母、数字和连字符 `-`。
- 长度保持在 1 到 64 个字符之间。
- 不能以连字符开头或结尾。
- 不要出现连续连字符。
- 不要使用特定厂商或产品的保留前缀。

## `description` 规则

- 用自然语言写触发条件和适用场景。
- 长度保持在 1 到 1024 个字符之间。
- 不能为空。
- 不要包含 XML 尖括号，例如 `<` 或 `>`。
- 不要塞实现细节、代码片段或执行逻辑。

## 可选字段

- `license`：只有在确实需要声明授权协议时再写。
- `compatibility`：只有在需要说明环境要求、安装前提、网络条件或宿主限制时再写。
- `allowed-tools`：只有在目标平台支持该字段，且需要提前声明允许工具时再写。
- `metadata`：用于补充结构化信息；只写真正有搜索、分类、维护价值的字段。

## 推荐的 `metadata` 子字段

- `author`：作者或组织。
- `version`：版本号。
- `mcp-server`：关联的 MCP 服务名。
- `category`：分类。
- `tags`：标签数组。
- `documentation`：外部文档链接。
- `support`：反馈或支持联系方式。

## 编写原则

- 头部字段越少越好，只保留有实际意义的内容。
- 通用 Skill 先依赖 `SKILL.md` 自身成立，不要把平台专属 companion 文件当成必填结构。
- 如果用户没有明确指定宿主产品，就不要预设某个平台专属字段或侧车文件。
