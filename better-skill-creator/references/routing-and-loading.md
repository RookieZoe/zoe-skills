# 路由与按需加载

## `description` 写法

`description` 不是功能简介，而是路由条件。

推荐格式：

```yaml
description: "适用：……；不适用：……；产出：……。"
```

要求：

- 一行写完
- 短、准、低歧义
- 说明什么时候该用、什么时候不要用、最终产出什么
- 不写背景故事，不写实现细节

## `SKILL.md` 路由段落

正文开头优先包含四类信息：

- 适用
- 不适用
- 产出
- 反例

反例不是可选项。至少给 2 到 4 个反例，用来帮路由避开相邻但不匹配的需求。

## 按需加载原则

- 系统提示只应该常驻短描述，而不是完整工作手册。
- `SKILL.md` 只保留流程和约束。
- 详细规则放进 `references/`。
- 固定输出骨架放进 `assets/`。
- 确定性代码放进 `scripts/`。

## 典型错误

- `description` 太长，像 README 简介。
- `description` 太短，像“help with backend”。
- `SKILL.md` 里塞进几百行工作手册，不拆 supporting files。
- 一个 skill 同时覆盖太多相邻任务，导致任何请求都可能命中。

## 副作用规则

如果 skill 会：

- 调付费 API
- 写外部系统
- 发消息、下单、上传、删除、部署

则必须：

- 在正文中写明确认条件
- 优先批量操作，避免逐条循环
- 遇到限流或 429 时等待并降低并发，而不是热循环重试
