# Skill 立项判断

先回答：这件事到底应不应该被做成 Skill。

## 适合做成 Skill 的信号

- 这是一个会反复出现的任务，而不是一次性需求。
- 触发条件相对稳定，能被一句短描述概括。
- 输出物清晰，能说清“最终会产出什么”。
- 这项能力未来还会被其他 Agent、其他项目或其他用户复用。
- 需要绑定脚本、模板、参考文档、检查清单或外部工具。
- 重点在“如何稳定做这件事”，而不是“如何像某个人说话”。

## 不适合做成 Skill 的信号

- 只是一次性 Prompt。
- 低频任务，用一份普通文档就够。
- 这是产品代码里应被硬编码的固定逻辑，而不是交给模型路由的能力。
- 需求范围太大，像“帮我做后端”“帮我处理所有文档”“帮我 review、debug、deploy 一切”。
- 本质是在模仿一个人，而不是沉淀一套可复用 SOP。

## 输出决策

只允许以下三种结论之一：

- 新建 skill
- 升级现有 skill
- 不做 skill，改用文档、模板、一次性 prompt 或产品内固定流程

## 边界提醒

- Skill 更像手册，不是另一个 Agent。
- Agent 负责理解意图和拆计划，Skill 负责封装某个明确能力。
- 如果一个需求拆不开主任务边界，先拆能力，再谈 Skill。
